1

Как работает форма

в лабораторной: A1A2A3

Форма — часть страницы, в которой посетитель вводит данные и отправляет их на сервер. Вход по паролю, строка поиска, оформление заказа, комментарий — всё это формы.

Форма состоит из трёх частей:

  • элемент <form> — он окружает всё остальное;
  • поля — элементы, в которые вводят или в которых выбирают значения;
  • кнопка отправки.
<form action="/register" method="get">
  Имя:<br>
  <input type="text" name="firstname"><br>
  Фамилия:<br>
  <input type="text" name="lastname"><br><br>
  <input type="submit" value="Отправить">
</form>

После нажатия кнопки браузер собирает значения всех полей формы и отправляет их на сервер одним запросом.

Куда и как: атрибуты action и method

  • action — адрес, на который уйдут данные. Если его не написать, данные уйдут на адрес самой страницы.
  • method — способ отправки: get или post. Если его не написать, будет get.

Под каким именем: атрибут name

У каждого поля есть атрибут name. Это имя, под которым значение придёт на сервер. На сервер уходят пары «имя=значение»: слева то, что написано в name, справа то, что ввёл посетитель.

Частая ошибка

Поле без name на сервер не отправляется — совсем. Форма выглядит рабочей, кнопка нажимается, но этого значения сервер не получит. Убери name у одного из полей в примере выше и отправь форму ещё раз.

Два способа отправки

  • GET. Пары дописываются к адресу после знака ? и разделяются знаком &. Их видно в адресной строке: /register?firstname=Anna&lastname=Koval.
  • POST. Адрес остаётся без добавок. Пары передаются внутри запроса, после служебных строк. Эта часть запроса называется телом.

Заполняй форму и переключай способ отправки. Справа — запрос, который браузер отправил бы на сервер.

Интерактив

Что уйдёт на сервер

Попробуй ввести имя русскими буквами или с пробелом. Буквы превратятся в коды со знаком %, пробел — в +. Так браузер кодирует символы, которые в адресе недопустимы. Сервер сам расшифрует их обратно. Подробнее — в разделе 6.

Если знаешь C#

Сервер получает набор пар «строка → строка», как Dictionary<string, string>. Все значения приходят строками — даже число из числового поля. Превращать строку в число или дату будет серверный код.

Зачем это бэкендеру

В ASP.NET Core значения формы попадают в параметры метода по именам: значение поля с name="email" придёт в параметр email. Опечатка в name — и параметр окажется пустым, хотя форма «работает».

Коротко

  • action — куда отправить, method — каким способом.
  • На сервер уходят пары «имя=значение». Имя берётся из атрибута name.
  • GET кладёт пары в адрес, POST — в тело запроса.

Поля для ввода и подписи

в лабораторной: A1A2B1

Почти все поля создаёт один элемент — <input>. Это тег без пары. Каким будет поле, решает атрибут type.

ЗаписьКакое поле получится
type="text"одна строка текста. Этот тип действует, если type не указан
type="password"текст скрыт точками
type="email"адрес почты. Браузер проверит, что введённое похоже на адрес

Подпись к полю

Текст рядом с полем для браузера — просто текст. Браузер не знает, к какому полю он относится. Связь задаёт элемент <label> — подпись. Связать подпись с полем можно двумя способами.

  1. Полю дают атрибут id, а в <label> пишут атрибут for с тем же значением.
  2. Поле кладут прямо внутрь <label>. Тогда for и id не нужны.
<form>
  <label for="email">Почта:</label>
  <input type="email" id="email" name="email"><br>

  <label><input type="checkbox" name="news"> Получать новости</label><br>

  <input type="checkbox" name="ads"> Получать рекламу
</form>

Нажми на слово «Почта»: курсор встанет в поле. Нажми на «Получать новости»: флажок переключится. А слова «Получать рекламу» — обычный текст, нажатие на них ничего не даёт.

Подпись нужна по двум причинам. Во-первых, в поле проще попасть мышью или пальцем. Во-вторых, программы, которые читают страницу вслух, называют подпись, когда человек переходит в поле.

Частая ошибка

Путать id и name. Это разные атрибуты с разной работой. id нужен странице: по нему <label> находит своё поле. name нужен серверу: под этим именем придёт значение. Им часто дают одинаковые значения, но писать нужно оба.

Начальное значение и подсказка

  • value — значение, которое стоит в поле сразу. Если посетитель его не изменит, оно и отправится.
  • placeholder — бледная подсказка в пустом поле. При вводе она исчезает. На сервер не отправляется.
<form action="/order" method="get">
  <label for="city">Город:</label>
  <input type="text" id="city" name="city" value="Киев"><br>
  <label for="name">Имя:</label>
  <input type="text" id="name" name="name" placeholder="Как к тебе обращаться?"><br>
  <input type="submit" value="Отправить">
</form>

Отправь эту форму, ничего не вводя. Город уйдёт на сервер, а имя — пустым: подсказка значением не считается.

Несколько строк текста

Для длинного текста есть элемент <textarea>. Это парный тег. Размер задают атрибуты rows (сколько строк видно) и cols (ширина в символах). Текст между тегами — начальное значение, обычно там пусто.

<form action="/feedback" method="post">
  <label for="comment">Комментарий:</label><br>
  <textarea id="comment" name="comment" rows="4" cols="35"></textarea><br>
  <input type="submit" value="Отправить">
</form>

Звёздочка у обязательного поля

Обязательные поля принято отмечать красной звёздочкой. Чтобы оформить часть строки, её оборачивают в элемент <span>. Сам по себе он ничего не меняет. Он только отделяет кусок текста, которому через атрибут style задают оформление.

<label for="n">Имя<span style="color: red;">*</span></label><br>
<input type="text" id="n" name="name">
Другие типы полей
ЗаписьДля чего
type="tel"номер телефона. На телефоне откроется цифровая клавиатура
type="url"адрес сайта. Браузер проверит, что он начинается с протокола
type="search"строка поиска
type="time"время
type="range"ползунок для выбора числа из диапазона
type="color"выбор цвета

Если браузер не знает какой-то тип, он покажет обычное текстовое поле.

Коротко

  • Поле — это <input>, его вид задаёт type. Длинный текст — <textarea>.
  • У каждого поля есть подпись <label>, связанная через for и id.
  • value — начальное значение, placeholder — подсказка, которая не отправляется.
3

Выбор из готовых вариантов

в лабораторной: A1A3B1

Не всё нужно вводить с клавиатуры. Часто удобнее выбрать из готового. Для этого есть флажки, переключатели и списки.

Флажок

Флажок — это <input type="checkbox">. Каждый флажок отмечается отдельно, так что выбрать можно сколько угодно вариантов.

  • value — что уйдёт на сервер, если флажок отмечен. Без value уйдёт слово on.
  • checked — атрибут без значения: флажок отмечен заранее.
<form action="/cart" method="get">
  <label><input type="checkbox" name="food" value="bread" checked> Хлеб</label><br>
  <label><input type="checkbox" name="food" value="milk"> Молоко</label><br>
  <input type="submit" value="Отправить">
</form>

Важная особенность

Неотмеченный флажок не отправляется вообще. Сервер не получит ни слова «нет», ни пустого значения: пары с этим именем в запросе просто не будет.

Переключатель

Переключатель — это <input type="radio">. Из группы переключателей можно выбрать только один. Группу образуют переключатели с одинаковым name. Значения value у них разные.

<form action="/cart" method="get">
  <label><input type="radio" name="drink" value="water"> Вода</label><br>
  <label><input type="radio" name="drink" value="juice" checked> Сок</label><br>
  <input type="submit" value="Отправить">
</form>

Частая ошибка

Дать переключателям разные name. Тогда они перестают быть группой, и отметить можно все сразу. Поменяй в примере одно из имён и проверь.

Выпадающий список

Список создают два элемента: <select> — сам список, <option> — один вариант в нём.

  • name пишется у <select>.
  • value пишется у каждого <option>.
  • selected — атрибут без значения: вариант выбран заранее.

На сервер уходит value выбранного варианта, а не текст, который видит посетитель. Если у <option> нет value, уйдёт его текст.

<form action="/delivery" method="get">
  <label for="country">Страна:</label>
  <select id="country" name="country">
    <option value="ua">Украина</option>
    <option value="pl">Польша</option>
    <option value="cz" selected>Чехия</option>
  </select>
  <input type="submit" value="Отправить">
</form>

Если знаешь SQL

В value варианта обычно кладут первичный ключ записи, а в текст — её название. Посетитель видит название, сервер получает ключ и по нему находит запись в таблице.

Список с группами и выбором нескольких вариантов

  • multiple — атрибут без значения у <select>: можно выбрать несколько вариантов. Для этого удерживают клавишу Ctrl.
  • size — сколько строк списка видно сразу. Список перестаёт быть выпадающим.
  • <optgroup label="…"> — группа вариантов с заголовком. Сам заголовок выбрать нельзя.
<form action="/resume" method="get">
  <label for="skills">Что умею:</label><br>
  <select id="skills" name="skills" multiple size="6">
    <optgroup label="Языки">
      <option value="html">HTML</option>
      <option value="sql">SQL</option>
    </optgroup>
    <optgroup label="Инструменты">
      <option value="git">Git</option>
      <option value="vscode">VS Code</option>
    </optgroup>
  </select><br>
  <input type="submit" value="Отправить">
</form>

Выбери два варианта и отправь форму. Каждый выбранный вариант уходит отдельной парой с одним и тем же именем: skills=html&skills=git.

Зачем это бэкендеру

Серверный код должен быть готов к трём случаям: значения с таким именем нет совсем (флажок не отмечен), значение одно, значений несколько (несколько флажков или список с multiple). Это частый источник ошибок на сервере.

Коротко

  • Флажок отправляется, только если отмечен.
  • У переключателей одной группы одинаковый name и разные value.
  • Из списка уходит value выбранного <option>.
4

Кнопки, группы и особые поля

в лабораторной: A1A2B1

Кнопки

Кнопку создаёт парный элемент <button>. Текст между тегами — надпись на кнопке. Что кнопка делает, определяет атрибут type.

ЗаписьЧто делает кнопка
type="submit"отправляет форму
type="reset"возвращает всем полям начальные значения
type="button"сама ничего не делает. Нужна для JavaScript, он начнётся в модуле 3

Если у кнопки внутри формы не указан type, она считается кнопкой отправки.

<form action="/login" method="post">
  <label for="login">Логин:</label>
  <input type="text" id="login" name="login"><br>
  <button type="submit">Войти</button>
  <button type="reset">Очистить</button>
</form>

Есть и старый способ: <input type="submit"> и <input type="reset">. Работают так же. Надпись задаётся в атрибуте value. Если value не написать, надпись поставит браузер — на языке своих настроек, поэтому на разных компьютерах она может отличаться.

Группа полей

Связанные поля объединяют в группу. <fieldset> рисует вокруг них рамку. <legend> — заголовок группы, он пишется первым внутри <fieldset>.

<form action="/order" method="post">
  <fieldset>
    <legend>Доставка</legend>
    <label><input type="radio" name="delivery" value="post" checked> Почта</label><br>
    <label><input type="radio" name="delivery" value="courier"> Курьер</label>
  </fieldset>
  <br>
  <button type="submit">Оформить</button>
</form>

Выбор файла

Поле <input type="file"> открывает окно выбора файла. Атрибут accept ограничивает вид файлов: accept="image/*" — только изображения.

Чтобы на сервер ушёл сам файл, у формы должны быть два атрибута: method="post" и enctype="multipart/form-data". Без них уйдёт только имя файла.

<form action="/upload" method="post" enctype="multipart/form-data">
  <label for="photo">Фотография:</label>
  <input type="file" id="photo" name="photo" accept="image/*"><br>
  <button type="submit">Загрузить</button>
</form>

Надпись на кнопке выбора файла ставит браузер. В HTML её изменить нельзя.

Скрытое поле

Поле <input type="hidden"> на странице не видно, но вместе с формой оно отправляется. В нём передают служебные данные. Например, номер записи, которую редактируют.

Скрытое поле помогает и с флажком. Неотмеченный флажок не отправляется, а серверу бывает нужен явный ответ «нет». Тогда перед флажком ставят скрытое поле с тем же именем:

<form action="/rules" method="get">
  <input type="hidden" name="agree" value="no">
  <label><input type="checkbox" name="agree" value="yes"> Принимаю правила</label><br>
  <button type="submit">Отправить</button>
</form>

Флажок не отмечен — уходит одна пара agree=no. Отмечен — уходят обе, agree=no и agree=yes, и серверный код выбирает нужную.

Частая ошибка

Считать скрытое поле секретным. Оно скрыто только от глаз: его видно в коде страницы, а значение легко подменить в DevTools. Пароли и цены в нём не хранят, а на сервере его значение проверяют так же, как любое другое.

Поле, которое нельзя изменить

  • disabled — поле выключено: изменить его нельзя, и на сервер оно не отправляется.
  • readonly — изменить нельзя, но значение отправляется.
<form action="/profile" method="get">
  Логин: <input type="text" name="login" value="anna" readonly><br>
  Тариф: <input type="text" name="plan" value="базовый" disabled><br>
  <button type="submit">Отправить</button>
</form>

Коротко

  • Кнопка в форме без type отправляет форму.
  • <fieldset> и <legend> объединяют поля в группу с заголовком.
  • Файл уходит только при method="post" и enctype="multipart/form-data".
  • Скрытое и выключенное поля: первое отправляется, второе нет.
5

Проверка данных в браузере

в лабораторной: A1A2B1

Браузер умеет проверить данные до отправки. Если проверка не пройдена, форма не отправляется, а возле поля появляется сообщение. Проверка включается атрибутами поля.

АтрибутЧто проверяет
requiredполе обязательное: пустым его не отправить
type="email"значение похоже на адрес почты
min, maxнаименьшее и наибольшее допустимое число или дата
stepшаг между допустимыми числами
minlength, maxlengthнаименьшая и наибольшая длина текста
patternтекст соответствует образцу
<form action="/order" method="post">
  <label for="name">Имя:</label>
  <input type="text" id="name" name="name" required><br>
  <label for="email">Почта:</label>
  <input type="email" id="email" name="email" required><br>
  <label for="qty">Количество, от 1 до 10:</label>
  <input type="number" id="qty" name="qty" min="1" max="10" value="1"><br>
  <label for="pass">Пароль, не короче 8 символов:</label>
  <input type="password" id="pass" name="pass" minlength="8" required><br>
  <button type="submit">Отправить</button>
</form>

Сообщения об ошибках пишет сам браузер, на языке своих настроек. Пока в форме есть хотя бы одна ошибка, запрос не уходит.

У флажка required работает по-своему: флажок должен быть отмечен. Так делают обязательное согласие с правилами. У переключателей required означает, что в группе нужно выбрать один из вариантов.

Числа и даты

Атрибуты min, max и step работают вместе. Запись <input type="number" min="0" max="25" step="0.5"> разрешает числа от 0 до 25 с шагом 0,5: подойдут 0, 0.5, 1, 1.5 и так далее. Дробная часть в коде пишется через точку.

Для дат min и max записывают в виде «год-месяц-день»: min="1960-01-01".

Выбери правило, вводи значения и смотри, пропустит ли их браузер.

Интерактив

Проверка значения

Образец

Атрибут pattern описывает, как должно выглядеть значение. Образец записывается на особом языке — регулярных выражений. Учить этот язык сейчас не нужно. Достаточно читать простые образцы: pattern="[0-9]{6}" означает «ровно шесть цифр».

Как сообщить требования заранее

Посетитель должен узнать требования до того, как ошибётся. Способов три, их можно сочетать:

  • написать требование прямо в подписи: «Пароль, не короче 8 символов»;
  • показать пример в placeholder;
  • добавить атрибут title. Его текст всплывает при наведении мыши, а для поля с pattern браузер добавляет его к сообщению об ошибке.
<form action="/order" method="post">
  <label for="code">Почтовый индекс, шесть цифр:</label>
  <input type="text" id="code" name="code" pattern="[0-9]{6}"
         placeholder="012345" title="Шесть цифр без пробелов" required><br>
  <button type="submit">Отправить</button>
</form>

Зачем это бэкендеру

Проверка в браузере — удобство для посетителя, а не защита. Запрос можно отправить и без формы, а атрибуты required и max любой уберёт в DevTools за несколько секунд. Поэтому серверная программа обязана проверить все данные ещё раз. Правило бэкенд-разработчика: данным из браузера не доверяют.

Примеры образцов для pattern
ОбразецЧто означает
[0-9]{6}ровно шесть цифр
[A-Za-z]{2,10}от двух до десяти латинских букв
[A-Za-z0-9_]+латинские буквы, цифры и знак подчёркивания, не меньше одного знака
\+38\(\d{3}\)\d{3}(-\d{2}){2}телефон в виде +38(051)240-04-40

Квадратные скобки перечисляют допустимые знаки. Фигурные задают, сколько раз они повторяются. Знак + после скобок означает «один раз или больше».

Коротко

  • required, min, max, step, minlength, pattern включают проверку в браузере.
  • Пока в форме есть ошибка, запрос не отправляется.
  • Сервер всё равно проверяет данные заново.

GET и POST: что выбрать и где смотреть данные

в лабораторной: A1A2A3B2

Оба способа передают одни и те же пары «имя=значение». Разница в том, где эти пары лежат в запросе.

GETPOST
Где лежат данныев адресе, после знака ?в теле запроса
Видны в адресной строкеданет
Адрес с данными можно сохранить в закладки или переслатьданет

Простое правило. Запрос только спрашивает — GET. Запрос что-то меняет на сервере или содержит пароль — POST.

Частая ошибка

Форма входа с method="get". Пароль попадёт в адресную строку, в историю браузера и в журналы сервера. Формы с паролями — всегда post.

Кодирование значений

В адресе допустимы не все символы. Поэтому браузер перед отправкой кодирует значения:

  • пробел заменяется на +;
  • русские буквы и знаки вроде & и = заменяются на коды со знаком %. Слово «Анна» превращается в %D0%90%D0%BD%D0%BD%D0%B0.

Сервер расшифровывает всё обратно сам. Вручную кодировать ничего не нужно. Важно только узнавать такие адреса и не пугаться их.

Форма для настоящего сервера

В action можно написать адрес чужого сайта. Тогда форма отправит запрос ему. Ниже — форма поиска по Википедии.

<form action="https://ru.wikipedia.org/w/index.php" method="get">
  <label for="s">Найти в Википедии:</label>
  <input type="text" id="s" name="search" value="HTML">
  <button type="submit">Искать</button>
</form>

Поле называется search не случайно. Сервер Википедии ждёт параметр именно с таким именем. Назови поле иначе — и сервер его не поймёт. Имена параметров задаёт сервер, форма под них подстраивается.

Где увидеть отправленные данные

GET. Посмотри в адресную строку после отправки: пары стоят после знака ?.

POST. Данные показывают инструменты разработчика:

  1. Нажми F12 и открой вкладку Network.
  2. Отправь форму.
  3. В списке появится новый запрос. Нажми на него.
  4. Открой вкладку Payload. В разделе Form Data перечислены все пары «имя — значение».

Для запроса GET на той же вкладке есть раздел Query String Parameters — в нём те же пары, уже расшифрованные.

Почему после отправки появляется ошибка

Пока у тебя нет серверной программы. Live Server умеет только отдавать файлы. Если форма отправит ему запрос POST или обратится по адресу, которого нет, он ответит ошибкой: на странице появится надпись вроде «Cannot POST».

Это нормально. Форма свою работу сделала: данные ушли, их видно в DevTools. Просто принять их пока некому.

Зачем это бэкендеру

Программа, которая принимает такие запросы, — это и есть бэкенд. В курсе по ASP.NET Core ты напишешь код, который получит эти пары, проверит их, сохранит в базу данных и вернёт ответ.

Коротко

  • GET — чтобы получить, POST — чтобы изменить или передать пароль и файлы.
  • Значения в адресе закодированы; сервер расшифрует их сам.
  • Данные GET видно в адресной строке, данные POST — в DevTools: Network → запрос → Payload.

Мини-итоги: минимум по теме

Это то, что нужно понимать после лекции. Списки типов и атрибутов учить наизусть не нужно — они есть в таблицах и справочниках выше.

  1. Форма собирает значения полей и отправляет их на адрес из action способом из method.
  2. На сервер уходят пары «имя=значение». Имя берётся из name. Нет name — значение не отправляется.
  3. GET кладёт пары в адрес после ?. POST кладёт их в тело запроса.
  4. У каждого поля есть подпись <label>, связанная с ним через for и id.
  5. Флажок отправляется, только если отмечен. У переключателей одной группы одинаковый name.
  6. Из списка уходит value выбранного <option>, а не его текст.
  7. Кнопка внутри формы без type отправляет форму.
  8. Атрибуты required, min, max, minlength включают проверку в браузере. Сервер проверяет данные заново.
  9. Отправленное видно в адресной строке (GET) или в DevTools: Network → запрос → Payload.

Проверь себя

Сначала ответь на вопрос про себя или вслух. Потом открой ответ и сравни.

Какие два атрибута формы определяют, куда и каким способом уйдут данные?

action — адрес, на который уйдут данные. method — способ отправки: get или post. Если их не написать, данные уйдут на адрес самой страницы способом GET.

В форме есть поле <input type="text" id="phone">. Посетитель ввёл номер и нажал «Отправить». Что получит сервер?

Этого значения сервер не получит. У поля нет атрибута name, а без него поле не отправляется. Атрибут id его не заменяет: он нужен странице, а не серверу.

Чем placeholder отличается от value?

value — настоящее значение поля: оно стоит в поле сразу и отправится на сервер, если его не изменить. placeholder — только подсказка: она исчезает при вводе и на сервер не отправляется.

В форме три переключателя с name="size" и разными value. Сколько пар с именем size уйдёт на сервер?

Одна — с value того переключателя, который выбран. Если не выбран ни один, не уйдёт ни одной.

В списке есть вариант <option value="pl">Польша</option>. Посетитель выбрал его. Что уйдёт на сервер: «Польша» или pl?

Уйдёт pl. Текст между тегами видит посетитель, а серверу отправляется value. Текст ушёл бы, только если бы атрибута value не было.

Форма входа содержит поле с паролем. Какой способ отправки выбрать и почему?

POST. При GET пароль окажется в адресной строке, в истории браузера и в журналах сервера. POST передаёт данные в теле запроса, в адрес они не попадают.

Внутри формы стоит кнопка <button>Сохранить</button>. Что произойдёт при нажатии?

Форма отправится. У кнопки не указан type, а внутри формы такая кнопка считается кнопкой отправки.

У поля стоят атрибуты required и max="10". Может ли серверная программа рассчитывать, что пустое значение или число 500 к ней не придёт?

Нет. Эти атрибуты проверяет браузер, а их легко убрать в DevTools. Запрос можно отправить и вообще без формы. Поэтому сервер проверяет все данные заново.
